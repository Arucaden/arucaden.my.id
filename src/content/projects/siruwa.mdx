> **SIRUWA (Sistem Informasi Rukun Warga Dua)** is a web-based digital governance platform, build to digitize and centralize neighborhood-level public services in specific village at Kota Batu.

---

### Executive Summary & Role

As part of 5-person development team, I helped build SIRUWA as **fullstack developer** to bridge the massive gap between community administrators (*Pengurus RW/RT*) and neighborhood residents (*Warga*). 

Let's be honest, managing a neighborhood is complicated. Before SIRUWA, everything such as resident data records and document requests to tracking monthly dues was done manually. We wanted to build a single digital ecosystem that handles all of this seamlessly.

We ended up with a powerful Laravel-based platform that not only digitizes document pipelines and financial health but actually features a smart Decision Support System (DSS) using fuzzy logic to ensure social assistance (*Bansos*) is distributed fairly and objectively!

---

### Key Features

- **Centralized Data Management:** A single source of truth for household data. Residents can submit profile update requests, and admins can approve them or bulk-import data via Excel.
- **Online Document Requests:** Residents can request administrative letters from their phones, upload files, and track the approval status in real-time. _No more knocking on the RT's door at 9 PM!_
- **Transparent Financial Ecosystem:** Dual-account ledger tracking (*Iuran Sampah* & *Iuran Kematian*). Residents upload payment proofs, and admins can track arrears and generate PDF audit reports.
- **Decision Support System (SPK Bansos):** A mathematical logic using Fuzzy Logic to objectively rank households for social aid based on income, utilities, taxes, and dependents.
- **Public Information Portal:** A modern landing page with interactive demographic charts, an organizational structure, a FullCalendar agenda, and rich-text news publishing.

---

### The Problem & The Solution

**The Problem:**
- **Paperwork Chaos:** Resident data was kept in dusty binders or messy spreadsheets. Errors, duplicates, and missing NIKs were everywhere.
- **Painful Document Requests:** Need an official letter? You had to physically track down the neighborhood leader during specific hours. Such a hassle.
- **Opaque Finances:** Tracking monthly waste collection and funeral funds manually meant lost physical receipts, uncollected arrears (*tunggakan*), and zero financial transparency.
- **Subjective Social Aid:** Distributing *Bansos* without data-driven scoring often caused drama, disputes, and accusations of bias. 

**The Solution:**
- **Digital Ecosystem:** A dedicated web portal where residents self-serve and admins validate. 
- **Automated Pipelines:** Document requests and financial payments are tracked digitally with clear status phases (Submitted -> Validated -> Completed).
- **Algorithmic Fairness:** The built-in DSS engine mathematically evaluates households so aid distribution is 100% objective and transparent.
- **Central Communication Hub:** An interactive public portal keeps everyone informed about agendas and community news.

### Technical Details & Architecture

Here is why we chose the technologies we used:
- **Laravel**: The absolute powerhouse for this project. We needed a robust MVC framework with built-in routing, Eloquent ORM, and secure authentication to handle complex multi-role workflows.
- **Tailwind CSS & Alpine.js**: We wanted the UI to look incredibly modern without the heavy JavaScript bundle of React or Vue. Alpine.js provided the perfect lightweight interactivity for modals and dropdowns.
- **Database**: MySQL for storing household data and aggregating metrics for the DSS engine.
- **Cloud Integrations**: Used Cloudinary API for reliable image/document uploads and DomPDF for generating those essential audit-ready financial reports.

> - **why Laravel?** When dealing with complex and big relational data (households, residents, payments, document pipelines) and role system, we need a framework that can handle the complexity efficiently + we dont have the resources to build everything from scratch.
> - **why Fuzzy Logic?** Real-world social aid isn't black and white. Trapezoidal membership functions allowed us to categorize incomes and taxes into Low/Medium/High fuzzy sets for a much fairer evaluation than raw cutoffs.

---

### Challenges & Learnings

Building a platform this comprehensive brought some serious challenges:
- **The DSS Math**: Implementing Fuzzy Logic in PHP from scratch was challenging. Translating mathematical membership functions into clean, testable code took serious research and debugging.
- **Role & Route Security**: Ensuring a resident couldn't accidentally (or intentionally) access financial ledgers or approve their own documents required strict middleware and session management.
- **State & File Management**: Handling file uploads for payment proofs and document attachments and syncing them seamlessly with Cloudinary was a difficult yet rewarding learning curve.
