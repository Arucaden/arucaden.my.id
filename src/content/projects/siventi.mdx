> **SIVENTI** (Sistem Informasi Inventaris Jurusan Teknologi Informasi) is a web-based inventory and asset loan management system. We built this as a Project-Based Learning (PBL) for the Department of Information Technology (JTI).

---

### Executive Summary & Role

As part of a 6-person development team, I helped build SIVENTI as **Frontend Developer** to digitalize and automate how our department handles asset tracking, borrowing submissions, and approvals. 

Before this, everything was done manually with paper logs and messy spreadsheets. We wanted to create a platform that actually makes life easier for both students borrowing equipment and the admins managing it. 

We made a dual-portal system: a catalog for users and a dashboard for administrators to track stock, approve loans, and monitor overdue items.

---

### Key Features

- **Interactive Item Selection:** Users can browse the catalog, add items to a cart, and set quantities based on real-time stock availability.
- **Automated Stock & Lifecycle Sync:** Stock counts update automatically across the database when admins approve loans or process returns.
- **Borrowing Quotas & Overdue Guards:** Built-in safeguards prevent users from hoarding equipment and automatically flag overdue loans.
- **Role-Based Portals:** Completely separate experiences for general users and department administrators, securely routed and authenticated (not separated app).
- **Central Audit History:** A global transaction log for admins to track every piece of equipment and who borrowed it.

---

### The Problem & The Solution

**The Problem:**
- **Paperwork:** Relying on physical logbooks meant slow approvals and high chances of losing records (also why IT department still relying on paper?).
- **No Real-Time Visibility:** Students would come to borrow something only to find out it was already taken or broken. Such a waste of time.
- **Lost Equipment:** Without automated tracking, it was super hard to monitor return deadlines, leading to missing or overdue assets.
- **Data Errors:** Manual spreadsheets made it way too easy to accidentally delete active records or mess up stock counts.

**The Solution:**
- **Centralized Web App:** Built a dedicated portal for users to request items and admins to manage them.
- **Smart Safeguards:** We added referential integrity and deletion guards. You can't just delete an item if someone is currently using it.
- **Automated Tracking:** The system handles the math. It knows exactly how many items are available, borrowed, or under maintenance at any given second.

---

### Technical Details & Architecture

Here is why we chose the technologies we used:
- **MySQL**: A relational database with a normalized schema and prepared statements to keep things secure and structured.
- **Vanilla Tech Stack**: We used PHP, HTML, CSS, and JavaScript for the entire application, no frameworks.
- **Native State Management**: Relied on PHP Sessions, Cookies, and `localStorage` to keep the user's cart intact.

> - **why vanilla techstack?** We wanted to truly understand the fundamental of web development before building using frameworks.

---

### Challenges & Learnings

Well this was one of my first major collaborative web projects, so we faced some challenges along the way, such as:
- **Building Custom MVC**: Creating an MVC framework from scratch was a bit challenging. It forced us to really understand routing, sanitizing URLs, and enforcing role-based route guards.
- **State and Cart Logic**: Managing the cart state with cookies and syncing it with real-time database stock limits required some trial and error. _(so many edge cases)_
- **Database Integrity**: Learning how to properly structure relational databases and use views/constraints so users can't break the system by deleting active loans.
- **Team Collaboration**: Working in a 6-person team on a single codebase meant we had to get really good at dividing tasks, communicating, and managing code merges. _This is my first git conflict anyway_

---

### Key Takeaways & Results

Building SIVENTI improved my core web development skills a lot, like:
- **Streamlined Workflow**: Successfully transformed a inefficient, paper-based process into a fast, automated digital system.
- **Strong Fundamentals**: Building the architecture from scratch solidified my understanding of PHP, OOP, and database design.
- **Real-World Impact**: The project wasn't just a coding exercise, it solved a complicated administrative problem.
